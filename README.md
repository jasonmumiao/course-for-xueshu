# 学术交流月余量看板

这是一个可部署到 Vercel 的课程余量看板。首页直接展示上一次刷新快照；刷新时在看板生成书签脚本，用户到学校系统里点击书签，脚本会在学校同源页面内轮换培养方案、读取 `dxkc` 余量、恢复原课程，并把结果回传到看板缓存。

## 使用方式

1. 打开看板，先看上一次公开快照。
2. 点 `刷新全部`，或在搜索框输入课程名/编号，让结果只剩一门后点 `刷新搜索结果`。
3. 也可以直接点表格每一行右侧的 `刷新`。
4. 弹窗里选择刷新间隔，把蓝色书签按钮拖到浏览器书签栏。
5. 点 `我已放好书签，跳转学校页面`。
6. 在学校页面登录后，点击刚拖好的书签。
7. 等进度面板跑完，脚本会恢复培养方案、回传结果，并自动跳回看板。

旧书签不会自动更新。每次改了刷新范围或间隔，都从弹窗重新拖一次书签。

## 单门课程刷新

推荐两种方式：

- 搜索框输入课程名或课程编号，直到页面只剩一门课，然后点 `刷新搜索结果`。
- 在表格里找到那门课，直接点右侧 `刷新`。

如果搜索结果不止一门，看板会提示继续缩小关键词。

## 排序和筛选

表头里的 `课程`、`总量`、`预选`、`余量`、`更新时间` 都可以点击排序，再点一次切换升序/降序。搜索框、类别、余量状态和冲突状态筛选可以一起使用。

## 模拟选课

表格的 `是否可选` 列用于本地模拟选课：

- 点击 `加入待选` 会把课程加入浏览器本地待选列表。
- 如果课程时间和已加入待选的课程重叠，按钮会变红并显示冲突。
- 可以用 `全部冲突状态` 筛选全部、不冲突或有冲突的课程。
- 课程时间来自已刷新快照里的 `上课时间地点`；没有刷新过时间的课程会显示 `时间未知`。

待选列表只保存在当前浏览器，不会提交到学校系统。

## 环境变量

在 Vercel 项目里建议配置：

```bash
APP_TOKEN=
SCHOOL_ORIGIN=https://yjsjy.uestc.edu.cn
REQUEST_DELAY_MS=300
KV_REST_API_URL=
KV_REST_API_TOKEN=
BLOB_READ_WRITE_TOKEN=
```

`APP_TOKEN` 是可选的回传保护口令；如果设置了，`/api/school-script` 会在服务端自动把它写入回传地址，页面上不需要用户粘贴 Token。

强烈建议配置 Vercel Blob 的 `BLOB_READ_WRITE_TOKEN`，或配置 `KV_REST_API_URL` 和 `KV_REST_API_TOKEN`，用于持久保存上一次余量快照。没有持久存储时会退回临时 `/tmp` 缓存，Vercel 换实例后可能丢失。

项目已安装 `@vercel/analytics`，静态页面通过 Vercel Web Analytics 脚本上报访问数据。需要在 Vercel Dashboard 中为项目开启 Web Analytics。

## 部署

```bash
npm install
npm run login
npm run deploy
```

部署完成后，请从 Vercel 正式网址生成书签。若从 `127.0.0.1` 本地预览生成书签，结果只会回传到本地预览，不会更新 Vercel。

## 本地预览

```bash
npm install
npm run dev
```

默认地址是 `http://127.0.0.1:4182/`。本地预览包含前端和主要 API，便于验证弹窗、书签生成和缓存回传。

## 接口

- `GET /api/courses`：课程目录。
- `GET /api/cache`：公开快照。
- `GET /api/school-script`：生成学校页面执行脚本。
- `POST /api/report-cache`：学校页面脚本回传余量结果。
- `POST /api/refresh-pair`、`POST /api/restore`、`GET /api/session`：旧版后端代请求备用接口。
