# 学术交流月余量看板

面向电子科技大学研究生 6 月学术交流月选课的小工具。

## Motivation

学术交流月的课程很多，但培养方案里每位同学一次只能选择两门。学校选课界面也只会展示当前已选两门课的选课情况和剩余人数。

这会带来一个很麻烦的问题：如果想知道其他课程还有没有余量，只能先退掉已有课程，再换选其他课程，进入选课界面查看，再继续重复这个过程。对想综合比较所有课程余量、上课时间和冲突情况的同学来说，这个流程非常低效，也容易把原本想保留的课程弄乱。

这个看板就是为了解决这个信息不透明的问题：通过一个书签脚本在学校页面同源运行，自动轮换培养方案里的学术交流月课程，每次读取当前两门课程在选课界面的余量，最后恢复最初选择的课程，并把所有结果汇总到公开看板。

## 这个工具能做什么

- 一次性查看学术交流月所有课程的容量、预选人数、剩余人数和更新时间。
- 没有登录学校系统时，也能看到上一位同学刷新后的公开快照。
- 可以刷新全部课程，也可以通过搜索或行内按钮只刷新单门课程。
- 支持按课程名、编号、院系、教师搜索。
- 支持按类别、余量状态、冲突状态筛选。
- 支持点击表头按课程、总量、预选、余量、更新时间排序。
- 支持本地模拟待选课程，并根据已刷新到的上课时间判断是否冲突。
- 支持点击课程名展开留言区，给具体课程留下选课提醒或经验。
- 支持导出 CSV。

## 使用方式

1. 打开看板，先查看上一次公开快照。
2. 点击 `刷新全部`，或搜索到某一门课后点击 `刷新搜索结果`，也可以直接点击表格行右侧的 `刷新`。
3. 在弹窗里选择请求间隔。
4. 把蓝色书签按钮拖到浏览器书签栏。
5. 点击 `我已放好书签，跳转学校页面`。
6. 在学校页面登录后，点击刚拖好的书签。
7. 等进度面板跑完。脚本会自动恢复培养方案、回传结果，并跳回看板。

旧书签不会自动更新。每次改了刷新范围或刷新间隔，都需要从弹窗重新拖一次书签。

## 单门课程刷新

推荐两种方式：

- 在搜索框输入课程名、课程编号、院系或教师，让结果只剩一门后点击 `刷新搜索结果`。
- 在表格里找到目标课程，直接点击右侧 `刷新`。

如果搜索结果不止一门，看板会提示继续缩小关键词。

## 模拟选课

表格的 `是否可选` 列用于本地模拟选课：

- 点击 `加入待选` 会把课程加入当前浏览器的待选列表。
- 如果课程时间和已加入待选的课程重叠，按钮会变红并显示冲突。
- 人数已满或超额的课程也可以加入待选；余量状态只作为参考，不会阻止本地规划。
- 可以用 `全部冲突状态` 筛选全部、不冲突或有冲突的课程。
- 课程时间来自已刷新快照里的 `上课时间地点`；没有刷新过时间的课程会显示 `时间未知`。

待选列表只保存在当前浏览器，不会提交到学校系统，也不会影响培养方案。

## 课程留言

点击表格里的课程名，可以展开这门课的留言区。留言会公开显示昵称、内容、时间和匿名来源编号。

出于浏览器能力限制，页面无法采集真实 MAC 地址。服务端会私有留存访问 IP、匿名 IP 指纹、粗略 IP 段和 User-Agent，用于限制刷屏和排查滥用；公开页面不会展示真实 IP。

## 共享与本地状态

所有同学共享的数据只有：

- 课程余量快照，包括总量、预选人数、余量、教师、时间地点等。
- 每门课程下面的公开留言内容。

只保存在每个人自己浏览器里的数据包括：

- 待选课程列表。
- 搜索关键词。
- 类别筛选、余量状态筛选、冲突状态筛选。
- 表格排序字段和排序方向。
- 生成书签时选择的刷新间隔。

页面里的 `清空筛选` 只会清空当前浏览器里的搜索词和筛选条件，不会清空待选课程，也不会影响共享快照或其他同学的页面。

## 安全边界

这个项目的设计目标是“不收集、不保存同学的学校登录 Token/Cookie”：

- 学校登录 Cookie 只留在同学自己的浏览器里。
- 刷新脚本运行在 `yjsjy.uestc.edu.cn` 学校页面内，依靠浏览器自己的登录态读取学校接口。
- 回传到看板的数据只包含课程余量、上课时间、教师、班级等公开选课信息。
- 看板前端不会要求粘贴学校 Token，也不会把学校 Cookie 写入 `localStorage`、URL 或仓库。
- Vercel Blob / KV / APP_TOKEN 等服务端环境变量不会提交到 GitHub，也不会写入静态前端文件。
- 如果配置了 `APP_TOKEN`，学校脚本拿到的是短期 HMAC 回传签名，不是原始 `APP_TOKEN`。
- 留言功能无法采集 MAC 地址；服务端私有留存访问 IP 和匿名指纹，公开页面只展示匿名来源编号，不展示真实 IP。

需要注意的是：公开看板的缓存是大家共同刷新的公共快照，不适合承载个人隐私信息。`APP_TOKEN` 用于保护回传接口，应该配置在 Vercel 环境变量里，不要写进代码、README 或浏览器控制台截图。如果不配置 `APP_TOKEN`，回传接口会主要依赖学校页面来源校验，防护强度更低。

## 环境变量

在 Vercel 项目里建议配置：

```bash
APP_TOKEN=
COMMENT_SALT=
SCHOOL_ORIGIN=https://yjsjy.uestc.edu.cn
REQUEST_DELAY_MS=300
REPORT_TOKEN_TTL_MS=21600000
KV_REST_API_URL=
KV_REST_API_TOKEN=
BLOB_READ_WRITE_TOKEN=
```

强烈建议配置 Vercel Blob 的 `BLOB_READ_WRITE_TOKEN`，或配置 `KV_REST_API_URL` 和 `KV_REST_API_TOKEN`，用于持久保存上一次余量快照。没有持久存储时会退回临时 `/tmp` 缓存，Vercel 换实例后可能丢失。

`REPORT_TOKEN_TTL_MS` 是学校脚本回传签名的有效期，默认 6 小时。

`COMMENT_SALT` 用于生成留言来源的匿名指纹。建议配置一个随机字符串；如果不配置，会回退使用 `APP_TOKEN`，再不配置则使用项目默认盐值。

项目已安装 `@vercel/analytics`，静态页面通过 Vercel Web Analytics 脚本上报访问数据。需要在 Vercel Dashboard 中为项目开启 Web Analytics。

## 部署

```bash
npm install
npm run login
npm run deploy
```

部署完成后，请从 Vercel 正式网址生成书签。若从 `127.0.0.1` 本地预览生成书签，结果只会回传到本地预览，不会更新 Vercel 正式站。

## 本地预览

```bash
npm install
npm run dev
```

默认地址是 `http://127.0.0.1:4182/`。本地预览包含前端和主要 API，便于验证弹窗、书签生成和缓存回传。

## 接口

- `GET /api/courses`：课程目录。
- `GET /api/cache`：公开快照。
- `GET /api/comments`、`POST /api/comments`：课程留言读取与提交。
- `GET /api/school-script`：生成学校页面执行脚本。
- `POST /api/report-cache`：学校页面脚本回传余量结果。
- `POST /api/refresh-pair`、`POST /api/restore`、`GET /api/session`：旧版后端代请求备用接口，需要配置 `APP_TOKEN` 后才会启用。
